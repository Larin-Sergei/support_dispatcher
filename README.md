
# Диспетчер заявок службы поддержки

Учебный проект по дисциплине «Алгоритмы и структуры данных».

Тема: «Бинарные деревья».

## Цель работы

Разработка консольного приложения для управления заявками
службы поддержки с использованием:

- бинарного дерева поиска (BST);
- максимальной двоичной кучи (Max Heap);
- алгоритма сортировки кучей (Heap Sort).

Все основные алгоритмы реализованы самостоятельно
без использования сторонних библиотек.

## Технологии

- Python 3.9+
- Стандартная библиотека Python
- unittest для автоматизированного тестирования
- PyCharm в качестве среды разработки

## Модель данных

Каждая заявка содержит:

| Поле | Тип | Описание |
|---|---|---|
| id | int | Уникальный идентификатор |
| title | str | Название заявки |
| priority | int | Приоритет заявки |

В консольном приложении используются положительные ID
и приоритеты от 1 до 10.

Чем выше приоритет, тем срочнее заявка.

При одинаковом приоритете первой обрабатывается
заявка с меньшим ID.

## Бинарное дерево поиска

Бинарное дерево поиска используется для хранения
и поиска заявок по идентификатору.

Для каждого узла выполняются условия:

- ID всех узлов левого поддерева меньше ID узла;
- ID всех узлов правого поддерева больше ID узла;
- повторяющиеся ID запрещены.

Реализованы следующие операции:

1. Вставка заявки.
2. Поиск по ID.
3. Удаление узла.
4. Прямой обход (NLR).
5. Симметричный обход (LNR).
6. Обратный обход (LRN).
7. Уровневый обход (BFS).
8. Подсчёт узлов.
9. Подсчёт листьев.
10. Вычисление высоты.
11. Поиск минимального и максимального ID.
12. Проверка свойств BST.

Высота дерева измеряется в количестве уровней:
пустое дерево имеет высоту 0.

## Максимальная двоичная куча

Куча реализована на основе массива Python.

Для элемента с индексом i:

- левый потомок: 2 * i + 1;
- правый потомок: 2 * i + 2;
- родитель: (i - 1) // 2.

Реализованы:

- build_heap — построение кучи;
- insert — добавление элемента;
- peek — просмотр максимума;
- extract_max — извлечение максимума;
- heapify_up — восстановление снизу вверх;
- heapify_down — восстановление сверху вниз;
- is_valid_heap — проверка свойств кучи.

Для работы с активными заявками куча строится
из текущего содержимого BST.

## Сортировка кучей

Функция heap_sort выполняет сортировку заявок
по убыванию приоритета.

Основные этапы:

1. Создание копии списка заявок.
2. Построение максимальной кучи.
3. Последовательное перемещение максимума в конец.
4. Восстановление свойства кучи.
5. Разворот полученного массива.

Встроенные функции sort и sorted не используются.

Исходный список остаётся неизменным.

## Возможности программы

1. Добавить заявку.
2. Найти заявку по ID.
3. Удалить заявку.
4. Показать все заявки.
5. Выполнить четыре обхода дерева.

8. Построить и показать максимальную кучу.

10. Сформировать итоговый отсортированный отчёт.
11. Загрузить демонстрационные данные.

## Анализ сложности

n — количество заявок.
h — высота бинарного дерева поиска.

### BST

| Операция | Типичный сбалансированный случай | Худший случай |
|---|---|---|
| Вставка | O(log n) | O(n) |
| Поиск | O(log n) | O(n) |
| Удаление | O(log n) | O(n) |
| Обход | O(n) | O(n) |
| Характеристики | O(n) | O(n) |
| Проверка BST | O(n) | O(n) |
| Поиск min/max | O(log n) | O(n) |

Память для хранения дерева: O(n).

Рекурсивные обходы и проверки:
дополнительная память O(h).

Уровневый обход:
дополнительная память O(n).

BST не является самобалансирующимся.
При неудачном порядке вставки дерево может
выродиться в связный список.

### Max Heap

| Операция | Время |
|---|---|
| Построение кучи | O(n) |
| Добавление | O(log n) |
| Просмотр максимума | O(1) |
| Извлечение максимума | O(log n) |
| Восстановление кучи | O(log n) |
| Проверка свойств кучи | O(n) |

Память для хранения кучи: O(n).

Построение кучи в данной реализации копирует
список входных заявок.

### Heap Sort

Временная сложность:

- лучший случай: O(n log n);
- средний случай: O(n log n);
- худший случай: O(n log n).

Дополнительная память реализации: O(n),
поскольку входной список копируется.

Сортировка не является стабильной в общем случае.

## Автоматизированное тестирование

В файле tests.py реализованы 36 тестов.

Проверяются:

- добавление, поиск и удаление заявок;
- все варианты удаления узлов BST;
- четыре обхода дерева;
- характеристики дерева;
- проверка свойств BST;
- построение максимальной кучи;
- операции вставки и извлечения;
- корректность восстановления кучи;
- сортировка заявок;
- одинаковые приоритеты;
- пустые структуры данных;
- взаимодействие BST, Max Heap и Heap Sort.

Для запуска:

    python tests.py

## Ограничения

Приложение является учебным.

Заявки хранятся в оперативной памяти.
После завершения программы данные не сохраняются.

BST не выполняет автоматическую балансировку.

В демонстрационном приложении приоритет
пользовательской заявки ограничен значениями 1–10.
